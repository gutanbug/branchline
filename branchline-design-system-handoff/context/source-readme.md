# Branchline

Git 브랜치 비교 중심의 한국어 UI 프로토타입입니다. GitKraken 전체 기능(G01–G45, `git-client-spec.md` 참고)을 구현한 제품은 아닙니다.

## 열기

Design Files에서 `branchline.html`을 브라우저로 열면 예제 데이터로 UI를 미리 볼 수 있습니다. 외부 이미지·폰트·라이브러리가 필요 없는 단일 HTML입니다.

**실제 Git 저장소에 연결하려면 Electron으로 실행해야 합니다.** Node.js와 npm이 있는 환경에서:

```sh
npm install
npm start
```

창이 열리면 상단의 **실제 저장소 열기** 버튼으로 로컬 Git 저장소 폴더를 선택하세요. 이후 화면은 시스템 `git` CLI(`child_process.execFile`, 인수 배열 방식, shell 미사용)로 다음을 실제로 실행합니다:

- 저장소 열기, 브랜치·태그·스태시·커밋 이력(log) 조회, 작업 트리 상태(status)
- 브랜치 생성·체크아웃, 스테이징/언스테이징, 커밋
- cherry-pick(체리픽 가져오기), 스태시 저장/적용
- 병합(merge)과 비인터랙티브 rebase — 사이드바 브랜치 목록에서 바로 실행
- 병합·리베이스·체리픽 충돌 시 배너로 충돌 파일 목록을 보여주고, 파일별 "현재 쪽/가져오는 쪽 사용"으로 해결하거나 전체 중단(`--abort`)·계속(`--continue`) 가능
- 워크트리 실제 추가(기존 브랜치 체크아웃 또는 새 브랜치 생성)·잠금/잠금 해제·제거 — 사용 중이거나 잠긴 워크트리는 실제 Git이 삭제를 막습니다
- 커밋 GPG/SSH 서명 — 저장소에 `user.signingkey`가 설정되어 있으면 커밋 화면에서 서명 여부를 선택할 수 있고, 이력의 각 커밋에 실제 `%G?` 서명 검증 상태(확인됨/실패/키 없음 등)를 표시합니다
- 서브모듈 실제 추가(원격 clone)·상태 확인(정상/초기화 필요/포인터 변경됨/충돌)·업데이트·비활성화(deinit) — 사이드바에 "서브모듈" 탭으로 표시(실제 저장소를 열었을 때만 노출)
- Git LFS 실제 설치(`lfs install --local`)·패턴 추적/해제(`lfs track`/`untrack`, `.gitattributes` 자동 스테이징)·관리 파일 목록과 다운로드 상태 — 환경 설정 다이얼로그에서 관리(git-lfs 미설치 시스템에서는 비활성 안내만 표시)
- GitHub Pull Request 실제 조회(읽기 전용) — origin이 `github.com` 저장소를 가리키면 "요청함" 탭에서 실제 GitHub REST API로 열린 PR 목록(제목·작성자·head→base·상태)을 불러옵니다. Personal Access Token은 선택 입력(비공개 저장소·API 한도 확장용)이며 창의 메모리에만 유지되고 파일에 저장하지 않습니다. PR 항목에서 "GitHub에서 열기"로 OS 기본 브라우저에서 실제 PR 페이지를 열 수 있고, 로컬에 해당 브랜치가 있으면 "커밋 비교"로 바로 이동합니다.
- 원격: `가져오기`(fetch --prune), `Pull`, `Push`(`-u origin <branch>`) — 자격 증명은 OS Git 자격 증명 저장소·SSH 에이전트를 그대로 사용합니다.
- 커밋 이력 표를 GitKraken 스타일로 정리: 그래프·날짜 열은 드래그(또는 열 경계에 포커스 후 화살표 키)로 폭을 조절할 수 있고, 해시 열은 없애고 행 우클릭 메뉴에서 전체/짧은 SHA 복사로 대체했습니다. 날짜 열은 항상 연-월-일 시:분:초까지 표시하고, 행 높이를 줄여 더 많은 커밋을 한 화면에 보여줍니다.
- 파일 단위를 넘어선 hunk(변경 덩어리) 단위 부분 스테이징 — 변경 파일 목록에서 "부분 스테이징" 버튼을 누르면 스테이징되지 않은/스테이징된 변경을 hunk별로 나눠 보여주고, 각 hunk를 개별적으로 스테이징·언스테이징·되돌리기(discard) 할 수 있습니다. 한 파일이 일부만 스테이징된 경우 "부분 스테이징됨"으로 표시합니다.
- 인터랙티브 리베이스 — 사이드바 브랜치 목록의 "인터랙티브 리베이스" 버튼으로 기준 브랜치부터 현재 브랜치까지의 커밋을 오래된 순으로 불러와 커밋마다 pick/reword(메시지 수정)/squash/fixup/drop을 지정하고 ▲▼로 순서를 바꿀 수 있습니다. 실행은 실제 `git rebase -i`를 시퀀스 에디터로 제어해 수행하며, reword로 지정한 커밋은 `edit`으로 멈춘 뒤 자동으로 `git commit --amend`로 메시지를 반영하고 계속 진행합니다. 충돌이 나면 기존 병합/리베이스 충돌 배너·계속하기/중단하기 흐름을 그대로 재사용합니다.
- 무시 규칙(.gitignore) 관리 — 변경 파일 목록에서 추적되지 않은 파일에 "무시하기"를 누르면 저장소 최상위 `.gitignore`에 해당 경로가 정확히 추가되고(중복 추가 방지), 추적 중인 파일에는 "추적 중단"으로 `git rm --cached`를 실행해 인덱스에서만 제외하고 디스크의 파일은 그대로 둡니다. "무시 규칙 편집" 버튼으로 `.gitignore` 전체 내용을 직접 열어 편집·저장할 수도 있습니다.
- 브랜치 우클릭 메뉴 + 상단 주요 작업 툴바 — 사이드바에서 브랜치를 클릭해도(기존과 동일하게) 그래프 미리보기만 될 뿐 실제 Git 상태는 바뀌지 않습니다. 실제 저장소 조작은 브랜치를 **우클릭**해서 여는 컨텍스트 메뉴로만 실행하도록 GitKraken과 동일하게 분리했습니다. 메뉴 항목: 브랜치 이름 복사, 체크아웃, 여기서 브랜치 만들기, 여기서 워크트리 만들기, 현재 브랜치로 병합, 현재 브랜치를 이 브랜치 위로 리베이스, 인터랙티브 리베이스, 현재 브랜치를 이 커밋으로 리셋(hard), 이 커밋 되돌리기(revert), **이름 바꾸기(신규)**, **삭제(신규 UI 연결 — 백엔드는 있었지만 화면에 연결되지 않았던 기능)**, 솔로/솔로 해제, 숨기기, 현재 브랜치와 비교. 원격 브랜치는 이름 복사·솔로·비교만 지원합니다(체크아웃 등은 로컬 브랜치 생성이 먼저 필요해 범위에서 제외).
  상단 헤더에는 Fetch(가져오기)·Pull·Push(실제 저장소일 때만) 옆에 **브랜치 생성**·**스태시**·**Pop**(둘 다 항상 노출, 대상 없으면 비활성화)·**터미널**(실제 저장소) 버튼을 GitKraken 툴바처럼 한 줄로 배치해 화면 어디에 있든 바로 실행할 수 있게 했습니다. "Pop"은 지금까지 미사용이던 `stashPop` API를 실제로 연결한 것입니다.
- 커밋 상세 → 파일별 File View/Diff View — 커밋을 클릭하면 오른쪽 상세 패널에 실제 `git diff-tree`로 조회한 변경 파일 목록(추가/수정/삭제/이름변경 배지, 이름변경은 이전 경로도 함께 표시)이 나타납니다. 파일을 클릭하면 메인 화면이 전용 "파일 보기" 화면으로 전환되어 File View(그 커밋 시점의 파일 전체 내용, `git show sha:path`)와 Diff View(그 커밋의 해당 파일 diff)를 토글할 수 있고, 이전/다음 파일 버튼으로 같은 커밋의 다른 변경 파일로 바로 이동할 수 있습니다. "← 커밋 이력으로"로 원래 화면에 복귀합니다.
- Solo / Hide(G06) — 사이드바 로컬 브랜치 각 항목에 "솔로"·"숨김" 버튼을 추가했습니다. 하나 이상의 브랜치를 솔로로 지정하면 커밋 그래프가 그 브랜치들의 조상 이력만(공통 조상 포함, 합집합) 모아서 보여주고, "숨김"을 누르면 사이드바 목록에서만 제외됩니다(그래프·체크아웃 등 실제 데이터에는 영향 없음). "전체 복구"로 솔로·숨김 상태를 한 번에 초기화할 수 있습니다.
- 브랜치별 커밋 파악 UX 개선 — 사이드바의 로컬·원격 브랜치 목록에 기본 브랜치(main/master) 대비 앞섬·뒤처짐(↑↓) 배지를 표시하고, 커밋 그래프 화면 상단에 현재 보고 있는 브랜치의 HEAD 커밋 정보(제목·작성자·전체 날짜시간, 서명 상태)와 기본 브랜치 대비 차이, "◯◯와 비교" 바로가기 버튼을 보여주는 브랜치 정보 바를 추가했습니다. 이미 브랜치·워크트리·원격 브랜치 클릭 시 그래프로 이동하던 기존 동작 위에, 이제 어떤 브랜치를 보고 있는지·기본 브랜치와 얼마나 다른지를 그래프를 스캔하지 않고도 한눈에 파악할 수 있습니다.
- 내장 터미널(G27) — 사이드바 "터미널" 탭에서 세션을 시작하면 저장소 작업 디렉터리를 cwd로 실제 셸(`$SHELL`, Windows는 `COMSPEC`)을 `child_process.spawn`으로 띄우고, 입력창에 입력한 명령을 실제 프로세스 stdin으로 전달·stdout/stderr를 그대로 표시합니다. 세션은 저장소를 전환하거나 앱을 종료할 때 자동으로 종료됩니다. ANSI 색상, vim 등 전체 화면 프로그램, 실시간 키 입력(TTY)은 지원하지 않고 줄 단위 명령 실행 결과만 보여주는 단순 셸 러너입니다.
- 여러 저장소 탭(G02) — "실제 저장소 열기"로 연 저장소는 상단에 탭으로 쌓이고, 탭을 클릭하면 해당 저장소의 실제 스냅샷을 다시 불러와 전환합니다. 탭 목록은 `localStorage`에 저장되어 앱을 재시작해도 마지막에 활성화했던 저장소가 자동으로 복원됩니다. 다만 각 탭이 완전히 독립된 화면 상태(선택한 브랜치·보기 모드 등)를 유지하지는 않고, 전환 시 그 저장소의 최신 상태를 새로 불러오는 방식입니다.
- 파일 이력·blame(G14) — 사이드바 "파일 이력" 탭에서 저장소 최상위 기준 상대 경로를 입력하면 실제 `git log --follow`로 이름 변경을 넘나드는 커밋 이력을, `git blame --porcelain`으로 HEAD 기준 줄별 작성자·커밋·요약을 보여줍니다.
- 이력 복원(reset/revert/reflog) — 커밋 상세 화면에서 선택한 커밋으로 Soft/Mixed/Hard 리셋을 실행하거나(Hard는 실행 전 확인창 표시), "되돌리기(revert)"로 해당 커밋을 취소하는 새 커밋을 생성할 수 있습니다. revert 충돌도 병합/리베이스와 동일한 충돌 배너·계속하기/중단하기로 처리됩니다. 사이드바 "이력 복구" 탭에서는 실제 `git reflog`를 시간순으로 보여주고, 각 시점으로 Mixed/Hard 리셋할 수 있습니다.

브라우저(비-Electron)에서 열거나 `실제 저장소 열기`를 누르지 않으면 이전과 동일한 예제 데이터 시뮬레이션으로 동작합니다. 아직 구현하지 않은 영역(인터랙티브 rebase의 순서 변경·squash·drop 편집, hunk 단위 충돌 병합 도구, GitHub/GitLab PR·MR 실제 연동, GPG 서명, 워크트리·서브모듈 실제 조작 등)은 `git-client-spec.md`의 기준표를 따릅니다.

## 핵심 흐름

1. 가져올 브랜치와 적용할 브랜치를 선택합니다.
2. 검색하거나 “차이만 보기”로 범위를 좁힙니다.
3. 일반 커밋을 선택한 뒤 “선택 커밋 가져오기”를 누릅니다.
4. 순서와 대상을 확인하고 적용합니다. 대상 브랜치에 예제 커밋이 추가됩니다.
5. 왼쪽 브랜치를 클릭하면 해당 브랜치의 조상 이력만 표시됩니다.

PR·MR 요청함에서도 같은 비교 화면을 엽니다. 스테이징·커밋·스태시·새 브랜치도 예제 데이터로 시험할 수 있습니다. 새로고침하면 초기 상태로 돌아갑니다.

## 파일

- `branchline.html`: 화면·스타일·예제 모델과 실제 저장소 연동 상호작용
- `electron-main.cjs`: Electron 진입점, IPC 핸들러(`git:*`), 열기 다이얼로그
- `preload.cjs`: contextBridge로 `window.gitAPI`만 좁게 노출(Node 접근 차단 유지)
- `git-backend.cjs`: 실제 `git` CLI 실행 모듈(`execFile`, 인수 배열, shell 미사용)
- `github-backend.cjs`: GitHub REST API 클라이언트(원격 URL 파싱, PR 조회/생성/병합, 오류 분류)
- `package.json`: Electron 실행 진입점과 의존성
- `git-client-spec.md`: 공식 문서 분석, 기능군 45개, 실제 Git/Electron 구현 명세와 미구현 범위
- `brand-spec.md`: 고정된 디자인 토큰
- `check-prototype.cjs`: 핵심 모델 검증

## 검증

```sh
npm test
```

스크립트 구문, 차집합·공통 조상, 필터, 숨겨진 조상 연결, 체리픽 순서·원본 보존·중복 방지를 검증합니다.

`git-backend.cjs`는 임시 로컬 저장소·bare 원격을 만들어 log/status/stage/commit/branch/checkout/cherry-pick/stash/push/fetch, merge/rebase 충돌 발생·해결·계속·중단(`--abort`), 워크트리 추가·잠금·잠금 상태에서의 삭제 차단·잠금 해제 후 삭제를 실제로 실행해 직접 확인했습니다. GPG 서명도 임시 GPG 키를 생성해 `user.signingkey` 설정 감지, `-S` 서명 커밋, `--no-gpg-sign` 미서명 커밋, `%G?`/`%GS` 서명 상태·서명자 파싱까지 실제로 검증했습니다. 서브모듈도 로컬 bare 저장소를 대상으로 실제 `submodule add`(clone) → 상태 조회 → `deinit`(작업 디렉터리 제거·미초기화 상태 전환) → `update --init`(재복원)까지 전 과정을 직접 실행해 확인했습니다. Git LFS는 로컬 저장소 단위 설치 여부(`--local` 스코프, 전역 설정과 혼동하지 않도록 별도 검증) → 패턴 추적 → 실제 LFS 포인터로 커밋 → 관리 파일 목록·다운로드 상태 조회 → 추적 해제까지 실행해 확인했습니다. GitHub 연동은 실제 origin URL 파싱(HTTPS/SSH 형식) → 실제 `microsoft/vscode` 공개 저장소에 라이브 조회(열린 PR 30건 수신 확인) → 404(존재하지 않는 저장소)·401/403(토큰 없음·rate limit) 오류를 실제 응답으로 구분해 검증했습니다. 다만 PR 생성·병합 API 호출(`createPullRequest`/`mergePullRequest`)은 코드만 구현했고, 제3자 저장소에 실제 쓰기 작업을 수행하지 않기 위해 라이브 실행은 하지 않았습니다 — 사용자가 소유한 저장소와 토큰으로 직접 검증이 필요합니다. hunk 단위 부분 스테이징은 한 파일에 서로 떨어진 두 변경 구간을 만든 임시 저장소에서 `git diff` 파싱(2개 hunk 인식) → 첫 번째 hunk만 `git apply --cached`로 스테이징 → `git status`/`git diff`/`git diff --cached`로 같은 파일이 스테이징된 부분과 안 된 부분으로 정확히 나뉘는지 → 언스테이징(`--cached --reverse`)과 되돌리기(`--reverse`)로 원상 복구까지 실제로 실행해 확인했습니다. 인터랙티브 리베이스는 임시 저장소에서 5개 커밋을 만들어 reword(메시지 변경)·pick·drop(커밋 제외)·squash(이전 커밋에 병합)를 한 번에 지정해 실행 → 최종 이력이 의도한 순서·개수·내용으로 남는지, drop한 커밋의 파일이 실제로 사라졌는지, squash된 커밋의 파일 내용이 합쳐졌는지 직접 확인했습니다. 또한 재배치 후 두 커밋이 같은 줄을 수정해 충돌이 발생하는 경우 `operationState`가 `rebase`로 유지되고 `conflictedFiles`가 정확히 채워지며 `abortOperation`으로 정상 복구되는 것도 확인했습니다. 다만 충돌이 reword 대기 중(commit --amend 전)에 발생하는 경우 이후 reword 메시지가 자동 적용되지 않고 수동 계속하기가 필요한 제약이 있습니다. reset/revert/reflog는 3개 커밋을 만든 임시 저장소에서 중간 커밋을 revert했을 때 실제로 충돌(`operationState`가 `revert`로 유지, `conflictedFiles`에 파일 포함)이 발생하고 `abortOperation('revert')`로 정상 복구되는 것, 그리고 별도 저장소에서 revert 커밋을 만든 뒤 `mixed` reset으로 이전 커밋까지 되돌리면 작업 디렉터리 내용과 상태가 기대대로 반영되는 것, reflog가 `%gd` 필드와 `--date=format`이 서로 충돌해 잘못 파싱되는 버그를 실제로 발견하고 인덱스 기반 `HEAD@{n}` 계산으로 수정한 뒤 5개 항목이 정확히 파싱되는 것을 직접 실행해 확인했습니다. .gitignore 관리는 추적되지 않은 파일을 무시 처리하면 `git status`에서 실제로 사라지는 것, 같은 패턴을 두 번 추가해도 중복되지 않는 것, 추적 중인 파일을 추적 중단하면 인덱스에서는 삭제(D)로 표시되면서 디스크 파일은 그대로 남는 것을 직접 실행해 확인했습니다. 파일 이력·blame은 파일을 `mv`와 동시에 내용도 편집한 커밋에서는 git의 기본 유사도 임계값 때문에 `--follow`가 이름 변경을 추적하지 못하는 실제 한계를 재현해 확인했고, 이어서 순수 이름 변경(rename만 있는 커밋) 뒤에 편집한 경우에는 `--follow`가 이름 변경 전 커밋까지 정확히 이어지고 blame이 바뀌지 않은 줄은 원래 작성자에게, 편집된 줄은 새 작성자에게 올바르게 귀속되는 것을 직접 실행해 확인했습니다. 여러 저장소 탭은 서로 다른 두 개의 임시 저장소를 만들어 각각 `git:snapshot`을 호출했을 때 서로 다른 브랜치·커밋이 정확히 분리되어 반환되는 것, 같은 저장소를 다시 조회했을 때 이전과 동일한 결과가 나오는 것(탭을 오갈 때 상태가 섞이지 않음)을 실제로 실행해 확인했습니다. 다만 탭 클릭·닫기 UI 상호작용과 `localStorage` 기반 탭 복원은 Electron 창의 실제 클릭이 필요해 GUI 클릭 테스트는 하지 못했고 코드 검토로만 확인했습니다. 내장 터미널은 Electron 없이 동일한 `child_process.spawn` 로직을 Node로 직접 실행해 셸 프로세스 기동 → stdin으로 `pwd`/`echo` 명령 전달 → stdout 수집 → `exit` 명령으로 정상 종료 코드(0) 확인까지 검증했습니다. 다만 이 프로젝트에는 Electron devDependency가 설치돼 있지 않아(별도 `npm install` 필요) `ipcMain`/`contextBridge`를 통한 실제 IPC 경로와 세션 자동 종료(저장소 전환·앱 종료 시)는 코드 검토로만 확인했고 라이브 실행은 하지 못했습니다. Electron 창을 띄운 end-to-end 클릭 테스트, Windows/Linux 실행, SSH 서명 형식(`gpg.format=ssh`), 중첩 서브모듈, LFS 원격 push/pull, GitLab/Bitbucket/Azure DevOps 연동도 검증하지 않았습니다 — 이 범위는 `git-client-spec.md`의 구현 순서 4–5단계에 남아 있습니다. 브랜치별 앞섬·뒤처짐(↑↓) 배지와 브랜치 정보 바는 이미 검증된 `compareRefs`/`reachable` 순수 함수를 그대로 재사용해 별도 Git 호출 없이 계산되며, main에서 2커밋·feature에서 2커밋씩 분기한 샘플 이력을 Node로 직접 구성해 ↑2 ↓2가 정확히 나오는 것과 자기 자신과 비교하면 0/0이 나오는 것을 검증했습니다. 데모 모드와 실제 저장소 모드가 동일한 계산 경로를 타므로 두 모드에서 일관되게 동작합니다. Solo/Hide의 합집합 계산도 서로 다른 조상을 공유하는 3개 브랜치 샘플 이력을 Node로 직접 구성해, 두 브랜치를 솔로로 지정했을 때 공통 조상은 포함하고 솔로하지 않은 브랜치의 고유 커밋은 제외되는 것을 검증했습니다. 파일별 File/Diff View는 modify·delete·add·rename이 섞인 임시 저장소를 만들어 `commitFiles`가 각 상태(M/D/A/R, rename의 이전 경로 포함)를 정확히 반환하는 것, 각 파일의 `diffFile(mode='commit')` 결과가 해당 파일의 실제 변경 내용과 일치하는 것, `fileAtCommit`으로 특정 커밋 시점의 파일 전체 내용을 정확히 가져오는 것, 삭제된 파일을 이전 커밋 기준으로 조회하면 git이 실제로 오류를 내는 것까지 실제 실행해 확인했습니다. 브랜치 컨텍스트 메뉴의 이름 바꾸기는 임시 저장소에서 실제 `git branch -m`으로 브랜치명이 바뀌는 것을, 삭제는 병합되지 않은 브랜치를 일반 삭제하면 실제로 실패(`is not fully merged`)하고 강제 삭제로 재시도하면 성공하는 전체 흐름을 라이브로 확인했습니다.

앱 시작 시 기본 화면을 커밋 그래프(`view='graph'`)로 바꿔 사이드바 메뉴를 클릭하지 않아도 그래프가 바로 보이도록 했습니다(데모 초기화 `resetDemo()`도 동일하게 그래프로 이동). 브랜치 비교는 전체 화면 전환 없이 모달(`openCompareModal`/`compareModalBody`)에서 바로 확인할 수 있도록 바꿨고, 브랜치 우클릭 메뉴에 "다른 브랜치와 비교" 항목을 추가해 현재 브랜치와 기본 브랜치(또는 자기 자신일 경우 다른 임의 로컬 브랜치)를 대상으로 모달을 띄우며, 브랜치 정보 바의 비교 버튼도 같은 모달을 열도록 통일했습니다. 모달 안에서 비교 대상 브랜치를 드롭다운으로 바꿀 수 있고, 필요하면 "전체 비교 화면에서 열기"로 기존 비교 화면으로 이동할 수 있습니다. 이 계산은 기존에 검증된 `compareRefs` 순수 함수를 그대로 재사용하므로 추가 Git 호출이나 새 검증이 필요 없었고, `npm test`로 스크립트 구문과 기존 모델 검증이 모두 통과하는 것을 확인했습니다.

사이드바 LOCAL/REMOTE 브랜치 목록에서 브랜치 이름 앞 브랜치 아이콘을 제거했습니다. 좁은 사이드바 폭에서 아이콘과 이름이 한 줄에 들어가지 못해 아이콘만 이름 위에 별도 줄로 떨어져 보이는 문제(스크린샷으로 확인)가 있었는데, 폴더 트리 아이콘은 그대로 두고 브랜치 리프 항목의 아이콘만 제거해 해결했습니다. 순수 마크업 변경이라 `npm test`로 확인했습니다.

사이드바에 "활동 로그"(G43) 탭을 추가했습니다. 기존 `notify()` 호출(앱 전체에서 알림에 이미 쓰이던 함수)을 그대로 가로채 시간·메시지·레벨(정보/오류)을 세션 메모리 배열에 기록하고, 최신 항목이 위로 오도록 표시합니다. 레벨 분류는 별도 상태값을 추가하지 않고 메시지 문자열에서 "실패"/"오류"/"충돌"/"이미 있습니다"/"찾을 수 없습니다" 등 자주 쓰이는 실패 패턴을 정규식으로 찾는 휴리스틱입니다 — 완벽한 분류기는 아니며, 이는 새로운 에러 메시지 문구를 추가할 때 이 패턴 목록에 없는 표현을 쓰면 "오류"로 분류되지 않을 수 있다는 뜻입니다(README에 한계로 명시). G43이 요구하는 "실패 원인과 재시도 방법 제공"은 별도 안내 문구 생성 로직을 추가하지 않았는데, 이 앱의 실패 알림 메시지들이 이미 원인과 다음 행동을 포함하도록 작성되어 있어(예: "병합 충돌: ... 충돌을 해결한 뒤 다시 완료를 진행해 주세요") 활동 로그가 그 메시지를 그대로 보여주는 것만으로 요구사항을 만족합니다. 로그는 브라우저 새로고침 없이 창을 띄운 동안만 유지되는 세션 메모리이며(다른 세션 전용 상태인 Solo/Hide, 왼쪽 고정과 동일한 방식), "기록 지우기" 버튼으로 수동 초기화할 수 있습니다. 실제 git 명령 실패 메시지(예: 존재하지 않는 브랜치 병합 시도)로 오류 항목이 올바르게 기록되고 분류되는 것을 Node로 정규식 매칭을 직접 실행해 확인했고, `npm test`도 통과했습니다.

Gitflow 단축 기능(G25)을 툴바의 "Gitflow" 버튼으로 추가했습니다. Feature/Release/Hotfix 각각 시작·완료를 지원하며, 새 백엔드 호출은 전혀 추가하지 않고 기존에 검증된 `createBranch`/`checkout`/`merge`/`tagCreate`/`deleteBranch` 호출을 정해진 순서로 조합했습니다. Feature 시작은 develop이 없으면 만들지 확인 후 `feature/이름`을 develop에서 분기해 체크아웃하고, Feature 완료는 develop으로 되돌아가 `--no-ff`로 병합한 뒤 브랜치를 삭제합니다. Release/Hotfix는 시작은 각각 develop/main에서 분기하고, 완료는 main에 no-ff 병합 → (태그 이름을 입력했다면) main에 태그 생성 → develop에도 no-ff 병합 → 브랜치 삭제까지 이어집니다. 기존 merge()는 `squash`/`ff-only` 전략만 지원했는데, Gitflow는 항상 병합 커밋을 남겨야 해서 `no-ff` 전략을 새로 추가했고, fast-forward가 가능한 상황에서도 실제로 병합 커밋(부모 2개)이 생기는 것을 라이브로 확인했습니다. 전체 흐름(feature 시작→완료, release 시작→완료+태그, hotfix 시작→완료+태그)을 임시 저장소에서 처음부터 끝까지 직접 실행해 브랜치가 정리되고 태그가 두 개(`v1.0.0`, `v1.0.1`) 남고 각 단계의 변경 내용이 develop/main에 올바르게 전파되는 것을 확인했습니다. 병합 충돌이 나는 경우도 별도 처리를 추가하지 않고 기존 충돌 배너/중단·계속 흐름을 그대로 재사용하도록 설계했으며, 실제로 develop과 feature가 같은 줄을 수정하게 만들어 충돌이 발생하고 `operationState`가 `merge`로, `conflictedFiles`에 파일이 채워지고, `abortOperation`으로 정상 복구되는 것까지 라이브로 검증했습니다.

환경 설정 화면에 Git 사용자 정보(user.name/user.email) 조회·수정 기능을 추가했습니다(G28 프로필 항목 중 외부 인증이 필요 없는 로컬 identity 부분). "이 저장소만"/"전역(모든 저장소)" 범위를 선택해 저장할 수 있고, 저장소 전용 값이 있으면 "저장소 전용 값 지우기"로 지워서 전역 설정을 다시 따르게 할 수 있습니다. 새 백엔드 함수 `identityConfig`(local/global 값을 각각 조회)·`setIdentity`·`unsetLocalIdentity`는 `HOME`을 임시 디렉터리로 격리한 상태에서 실제로 검증했습니다: 전역 설정만 있을 때 로컬 값이 비어 있는 것, 저장소 전용 값을 설정하면 로컬 값만 바뀌고 전역 값은 그대로인 것, 전역 범위로 저장하면 전역 설정이 바뀌는 것까지 확인했습니다. 이 과정에서 실제 버그를 하나 발견해 고쳤습니다 — `unsetLocalIdentity`가 `user.name`과 `user.email`의 `git config --unset`을 `Promise.all`로 동시에 실행했는데, 두 프로세스가 같은 `.git/config` 파일을 동시에 읽고 쓰면서 서로의 변경을 덮어써(레이스 컨디션) 이메일 삭제가 무시되는 것을 라이브 테스트로 재현했습니다. 두 unset을 순차 실행으로 바꿔서 해결했고, 수정 후 재검증까지 마쳤습니다.

이전에 남겨둔 백로그(태그 UI 연결·amend·저장소 생성/복제·파일 CRUD)를 이번에 모두 처리했습니다. `tagDelete`/`tagPush`는 백엔드·IPC는 있었지만 UI가 없었는데, 사이드바 태그 우클릭 메뉴(이름 복사·원격에 Push·삭제)로 연결했습니다. 커밋 폼에는 "마지막 커밋에 수정 추가(amend)" 체크박스를 추가했고, 체크하면 새로 만든 `commitMessage`(`git log -1 --format=%s\x1f%b`) 결과로 기존 제목·본문을 그대로 불러온 뒤 `amendCommit`(`git commit --amend`)을 호출합니다 — 본문을 새로 만든 이유는, 단순히 커밋 목록의 `title`(subject만 파싱)로 채우면 원래 커밋 본문이 사라지는 데이터 손실 문제가 있었기 때문입니다. 저장소 생성/복제는 헤더의 "저장소 열기 ▾" 버튼을 여러 옵션 모달로 바꿔 기존 저장소 열기 외에 "새 저장소 만들기"(`git init`)와 "원격 저장소 복제"(`git clone`)를 추가했습니다. 작업 디렉터리 파일 CRUD는 새 IPC(`readWorkingFile`/`writeWorkingFile`/`createWorkingFile`/`deleteWorkingFile`, 모두 저장소 경로 밖으로 벗어나지 못하도록 `path.resolve` 경계 검사)로 구현했고, 작업 변경 화면에 "새 파일" 생성, 파일별 "편집"(전체 내용을 읽어와 textarea로 저장), 추적되지 않은 파일의 "파일 삭제"를 추가했습니다. 이 5가지 백엔드 함수(`initRepo`/`cloneRepo`/`amendCommit`/`commitMessage`/작업 파일 CRUD)는 모두 임시 저장소에서 직접 실행해 검증했습니다: `initRepo`가 실제 `.git`을 만드는 것, `cloneRepo`가 bare 원격을 정상적으로 복제하는 것, 상대 경로 조작(`../../etc/passwd`)이 실제로 차단되는 것, 파일 생성 후 읽기·쓰기·삭제가 순서대로 반영되는 것, `amendCommit`이 커밋 개수를 늘리지 않고 메시지만 바꾸는 것, `commitMessage`가 여러 줄 본문을 subject/body로 정확히 분리하는 것까지 확인했습니다. 이 작업 중 기존 코드에서 실제 버그도 하나 발견해 함께 고쳤습니다: `openRepo`/`initRepo`/`cloneRepo` 호출 결과는 항상 `{ok, value}` 형태로 감싸져 오기 때문에, 사용자가 파일 선택 대화상자를 취소해도 `value`가 `null`일 뿐 결과 객체 자체는 참(truthy)이라 "취소했습니다" 분기를 타지 못하고 `mapSnapshot(null)`이 그대로 호출되어 예외가 발생하는 문제였습니다. 세 곳 모두 `!result.value` 기준으로 취소 여부를 판단하도록 수정했습니다.

사이드바를 GitKraken 원본처럼 `LOCAL`/`REMOTE`/`TAGS`/`STASHES` 영어 대문자 섹션 헤더로 통일하고, 브랜치 이름에 `/`가 포함되면(`feature/x`, `fix/y` 등) 자동으로 폴더 트리로 묶어 보여주도록 했습니다(`buildBranchTree`로 경로를 분해해 트리를 만들고 `renderBranchNode`가 재귀적으로 `<details>` 폴더를 그리며, 현재 브랜치를 포함한 폴더는 자동으로 펼쳐집니다). LOCAL과 REMOTE 양쪽에 동일한 트리 로직을 재사용했습니다. 폴더 트리 로직은 여러 단계로 중첩된 브랜치 이름 집합을 Node로 직접 시뮬레이션해 폴더가 알파벳순으로 정렬되고 현재 브랜치가 포함된 폴더만 자동으로 열리는 것을 확인했습니다. 브랜치·커밋 그래프 상단 툴바(가져오기/Pull/Push/브랜치/스태시/Pop/터미널)와 지난 턴에 추가한 브랜치 컨텍스트 메뉴 일부 항목이 한글·영어가 뒤섞여 있던 문제도 정리했습니다 — 원본 GitKraken 화면(image-5.png)이 이 액션들을 전부 영어로 표기하는 것을 기준으로 삼아 Fetch/Pull/Push/Branch/Stash/Pop/Terminal, Set Upstream으로 통일했고, 커밋 메시지·알림·설명 문구 등 나머지 한국어 UI는 그대로 유지했습니다. 마지막으로 그래프 화면 상단 브랜치 정보 바에 "작업 디렉터리 변경 N개 · 보기" 칩(변경 사항이 없으면 "작업 디렉터리 깨끗함")을 추가해, GitKraken의 "N file changes in working directory" 요약처럼 커밋 그래프를 보면서 바로 작업 변경 존재 여부를 확인하고 한 번의 클릭으로 작업 변경 화면으로 이동할 수 있게 했습니다.

브랜치 우클릭 메뉴를 GitKraken의 실제 브랜치 컨텍스트 메뉴 구성(Pull/Push/Upstream 설정, 병합·리베이스, 체크아웃, 워크트리·브랜치 생성, 체리픽, Reset(soft/mixed/hard) 및 Revert, 이름 변경·삭제, 브랜치/커밋 SHA/링크 복사, 숨기기·왼쪽 고정·솔로, 브랜치 비교, 태그 생성)를 기준으로 확장했습니다. AI 기반 "Explain Branch Changes" 항목은 외부 자격 증명 없이는 구현할 수 없어 의도적으로 제외했습니다. 새로 추가된 백엔드 함수는 `fetchBranch`(`git fetch origin branch:branch`로 체크아웃하지 않은 브랜치를 fast-forward만 갱신)와 `setUpstream`(`git branch --set-upstream-to`)이며, 두 함수 모두 원격 저장소를 둔 임시 로컬 저장소 쌍(`/tmp/bmenu-*`)에서 실제로 실행해 체크아웃된 브랜치는 안전하게 거부되는 것, 체크아웃되지 않은 브랜치는 정확히 fast-forward되는 것, upstream이 실제로 설정되는 것(`git branch -vv`로 확인)을 검증했습니다. 기존에 백엔드·IPC까지는 있었지만 UI에 전혀 연결되어 있지 않던 `tagCreate`도 이번에 컨텍스트 메뉴의 "여기에 태그 만들기"/"여기에 주석 태그 만들기"로 연결했고, 임시 저장소에서 라이트웨이트·주석 태그가 각각 올바른 `annotated` 플래그로 생성되는 것을 실제로 확인했습니다. 브랜치/커밋 링크 복사는 이미 검증된 GitHub 원격 감지 결과(owner/repo)를 재사용해 URL 문자열만 클립보드에 복사하므로 별도 네트워크 호출이 없고, GitHub 원격이 감지되지 않은 저장소에서는 해당 메뉴 항목 자체가 나타나지 않습니다. 왼쪽 고정(Pin to Left)은 세션 동안만 유지되는 클라이언트 상태(`pinnedRefs`)로, 솔로/숨기기와 같은 방식으로 저장 없이 동작합니다. 체리픽은 기존에 검증된 `cherryPick` IPC를 브랜치 헤드 커밋 하나에 대해 재사용한 것이라 별도 검증이 필요 없었습니다. `npm test`로 스크립트 구문을 확인했고, 실제 Electron 클릭을 통한 메뉴 렌더링·상호작용은 GUI 환경이 없어 코드 검토로만 확인했습니다.

사이드바 브랜치 목록에서 브랜치마다 항상 붙어있던 "솔로"/"숨김" 버튼을 없애고, 대신 이미 구현되어 있던 우클릭 드롭다운 메뉴(브랜치 이름 복사·솔로·숨기기·다른 브랜치와 비교 등)로만 노출하도록 정리했습니다. 브랜치 이름이 길 때 버튼 두 개 때문에 줄바꿈되며 읽기 어려워지던 문제(스크린샷으로 확인된 `feature/branch-filter`가 여러 줄로 쪼개지는 현상)를 해결했고, 브랜치 이름 영역에 `text-overflow:ellipsis`를 적용해 한 줄로 유지되도록 했습니다. 솔로 상태는 버튼 대신 "솔로" 텍스트 배지로만 표시합니다. 순수 마크업 정리라 `npm test`의 스크립트 구문 검사로 확인했고, 실제 브라우저 렌더링은 Electron GUI가 없어 코드 검토로만 확인했습니다.

사이드바에 "내 메모" 탭을 추가해 현재 브랜치에 한정된 개인 메모 공간을 만들었습니다. `localStorage`에 `저장소 경로:브랜치명`(데모 모드는 `demo:브랜치명`) 조합을 키로 저장하므로 같은 저장소 안에서도 브랜치별로 메모가 분리되고, 다른 저장소 탭이나 데모 모드와도 섞이지 않습니다. 입력 시 300ms 디바운스 후 자동 저장되며, 사이드바 탭에는 메모가 있는지 여부를 점(●) 표시로만 보여줘 다른 브랜치로 이동했을 때도 메모 존재 여부를 바로 알 수 있습니다. 서버 저장이 아닌 브라우저 로컬 저장이라는 한계(기기 간 동기화 없음, 저장소를 삭제해도 메모는 남음)를 README에 명시합니다. 이 기능은 순수 `localStorage` 읽기/쓰기라 Git 백엔드 검증이 필요 없었고, `npm test`로 스크립트 구문만 확인했습니다 — 실제 브라우저에서 입력·자동저장·브랜치 전환 시 분리되는 동작은 Electron GUI가 없어 코드 검토로만 확인했습니다.

사이드바에서 브랜치를 한 번 클릭하면 실제로는 아무 git 명령도 실행되지 않는데도 그래프·비교·메모·정보 바가 즉시 그 브랜치 기준으로 바뀌어, 마치 체크아웃이 일어난 것처럼 오해할 수 있는 문제가 있었습니다. 원인은 `branch`라는 변수 하나가 "실제 체크아웃된 HEAD"와 "지금 화면에서 보고 있는 브랜치"라는 서로 다른 두 의미를 동시에 맡고 있었기 때문입니다. 이를 분리해 `viewBranch`(보는 중인 브랜치 — 그래프/비교/메모/정보 바가 이 값을 따름)와 `branch`(실제 git HEAD — 커밋 대상, 병합·리베이스·스태시·리셋·리버트 등 모든 실제 작업의 대상, 사이드바 "현재" 배지가 이 값을 따름)로 나눴습니다. 이제 브랜치 단일 클릭은 `selectBranchView`로 `viewBranch`만 바꿔 화면 전환 없이 그래프/사이드바를 갱신하고, 더블클릭은 `showBranch`로 `viewBranch`를 바꾸면서 커밋 그래프 화면으로 이동합니다(요청하신 "더블클릭 시 커밋 이력을 볼 수 있도록" 요건). 실제 체크아웃은 `checkoutBranch`(내부에서 `git checkout` IPC 호출)로만 수행되며, 이 함수를 호출하는 진입점을 브랜치 우클릭 메뉴의 "체크아웃" 항목 하나로 좁혔습니다 — 이전에는 사이드바 브랜치 행마다 있던 인라인 "체크아웃" 버튼과 브랜치 정보 바의 "이 브랜치로 체크아웃" 버튼도 체크아웃을 실행할 수 있었는데, "checkout은 우클릭 메뉴 내에 있도록 구성해달라"는 요청에 맞춰 두 버튼을 모두 제거했습니다(병합/리베이스/인터랙티브 리베이스 인라인 버튼은 체크아웃이 아니므로 유지). 마지막으로, 실제 체크아웃된 브랜치를 항상 보여주는 위치가 없었던 문제를 사이드바 저장소 이름 아래 "현재 브랜치" 표시줄로 해결했습니다 — 이 표시줄은 항상 `branch`(실제 HEAD)를 보여주며, 지금 보고 있는 브랜치가 실제 체크아웃 브랜치와 다를 때만 "보기" 버튼이 나타나 클릭 한 번으로 실제 체크아웃 브랜치의 그래프로 돌아갈 수 있습니다. 브랜치 정보 바에도 보는 중인 브랜치와 실제 체크아웃 브랜치가 다르면 "체크아웃됨" 배지 대신 "보는 중 · 실제 체크아웃은 X"라는 문구로 구분해 보여줍니다. `mapSnapshot`은 저장소가 바뀌거나 보던 브랜치가 더 이상 존재하지 않을 때만 `viewBranch`를 `branch`로 재설정하도록 만들어, 체크아웃·커밋 같은 일반적인 상태 갱신 후에도 사용자가 보고 있던 브랜치가 임의로 바뀌지 않게 했습니다. `branch`를 실제 HEAD로 두는 기존 함수들(`commitWip`/`mergeBranch`/`rebaseOnto`/`resetBranchTo`/`pullRepo`/`pushRepo`/`syncHeader` 등)은 모두 그대로 두었고, `renameBranchAction`과 `resetDemo`에는 각각 이름이 바뀌거나 초기화되는 브랜치가 현재 보고 있던 브랜치와 같을 때 `viewBranch`도 함께 갱신하는 처리를 추가했습니다. 이 리팩터링은 변수 용도 분리와 마크업 변경이 중심이라 `npm test`의 스크립트 구문·순수 함수 검증으로 확인했고, 실제 Electron 창에서의 클릭·더블클릭·우클릭 상호작용은 GUI 환경이 없어 라이브로 테스트하지 못했으며 코드 검토로만 확인했습니다.

사이드바 섹션 헤더 중 아이콘이 없던 LOCAL/REMOTE/TAGS/STASHES 네 곳에 GitKraken 원본(image-8.png, image-7.png)을 참고해 아이콘을 추가했습니다. LOCAL은 모니터 아이콘, REMOTE는 클라우드 아이콘으로 원본과 동일하게 맞췄고, 원본 스크린샷에는 잘려서 보이지 않지만 이미 만들어져 있던 TAGS/STASHES 헤더에도 통일성을 위해 각각 태그·레이어(스택) 아이콘을 추가했습니다(브랜치 리프의 브랜치 아이콘, 폴더 트리의 폴더 아이콘은 기존에 이미 적용되어 있어 그대로 두었습니다). 기존 `icons`/`icon()` 헬퍼가 쓰는 획(stroke) 기반 SVG 경로 방식을 그대로 따라 새 경로 4개만 추가했고, 헤더 마크업에 `<svg class="ico">`를 인라인으로 끼워 넣었습니다. 순수 마크업 변경이라 `npm test`로 스크립트 구문을 확인했고, 실제 렌더링은 Electron GUI가 없어 코드 검토로만 확인했습니다.

커밋 그래프를 사이드바 탭 중 하나가 아니라 항상 떠 있는 기본 화면으로 바꿨습니다(image-9.png에서 지적하신 것처럼, 브랜치는 이미 체크아웃·사이드바 클릭/더블클릭으로 정해지므로 별도의 "조회할 브랜치" 드롭다운과 그 위 Header(브레드크럼·제목·설명)가 불필요했습니다). 사이드바 메뉴에서 "커밋 그래프" 항목 자체를 없앴고, 그래프 화면에서는 Header와 "조회할 브랜치" 셀렉트를 제거했습니다 — "이력 범위"(전체 조상 이력 / 다른 브랜치에 없는 이력) 셀렉트는 브랜치 선택과 무관한 별개 필터라 그대로 남기고 브랜치 정보 바 위에 단독으로 배치했습니다. 상단 툴바에 이미 있던 "Branch" 버튼과 중복이던 헤더 안의 "브랜치 만들기" 버튼도 함께 정리했습니다.

브랜치 비교·작업 변경·요청함·워크트리·내 메모·활동 로그·서브모듈·이력 복구·파일 이력·터미널·파일 보기 같은 나머지 화면은 전부 모달이 아닌 오버레이 패널로 바꿨습니다. `<main class="workspace">` 안에 `#content`(항상 현재 체크아웃/보는 중인 브랜치의 그래프를 그리는 기본 레이어)와 그 위를 절대 위치로 완전히 덮는 `#view-overlay`(호출되는 화면마다 내용을 채우는 레이어) 두 개를 두었고, `heading()` 헤더 컴포넌트에 "✕ 닫기" 버튼을 추가해 기본적으로 `switchView('graph')`(파일 보기는 `closeFileViewer()`)를 호출하도록 만들었습니다. 오버레이가 열리면 `#content`는 되돌아왔을 때 어색하지 않도록 가벼운 정적 그래프 스냅샷으로 바뀌고(상호작용 요소나 id가 전혀 없어 오버레이와 겹쳐도 충돌하지 않습니다), 닫으면 다시 완전한 인터랙티브 그래프로 다시 그려집니다. `<dialog>` 기반 모달과 달리 배경을 어둡게 가리지 않고 슬라이드 페이드 애니메이션으로 나타나는 일반 패널이며, 사이드바는 오버레이가 열려 있어도 계속 조작할 수 있습니다.

한 가지 예외는 "브랜치 비교" 화면입니다. 비교 화면은 그래프 화면과 커밋 목록·그래프 SVG·필터·체리픽 트레이·상세 패널을 그리는 코드(`getRows`/`renderHistory`/`drawGraph`/`renderTray`/`renderDetail`, 모두 `history-content`/`apply-tray`/`commit-detail` 같은 고정 id에 의존)를 그대로 재사용합니다. 이 로직을 통째로 복제하면 같은 id를 가진 엘리먼트가 두 곳에서 동시에 존재해 `document.getElementById`가 잘못된(보이지 않는) 엘리먼트를 가리키는 버그가 생길 수 있어, 대신 비교 화면이 열릴 때는 `#content`가 (다른 오버레이들과 마찬가지로) id 없는 정적 스냅샷으로 바뀌어 해당 id들을 비워주고, `#view-overlay`가 그 id들을 가진 진짜 비교 화면을 그립니다 — 기존 `view` 상태값이 그대로 `'compare'`가 되므로 공유 함수들의 동작은 전혀 바뀌지 않습니다. 이 방식 덕분에 새 렌더 함수(`renderCompareOverlay`)는 헤더와 비교용 브랜치 선택 UI만 새로 그리고, 핵심 로직은 검증된 기존 코드를 그대로 씁니다.

`renderChanges`/`renderRequests`(+ GitHub 실제 연동판)/`renderWorktrees`/`renderSubmodules`/`renderReflog`/`renderFileHistory`/`renderTerminal`/`renderNotes`/`renderActivityLog`/`renderFileViewerPanel`은 각자 독립적인 id를 쓰고 있어 그래프와 겹칠 일이 없으므로, `$('content').innerHTML=...`이던 부분을 `$('view-overlay').innerHTML=...`로 바꾸기만 했고 내부 로직은 손대지 않았습니다. 이 리팩터링은 렌더링 타깃과 마크업 구조 변경이 중심이라 `npm test`의 스크립트 구문·순수 함수 검증으로 확인했고, 실제 Electron 창에서 오버레이가 열리고 닫히는 애니메이션·상호작용은 GUI 환경이 없어 라이브로 테스트하지 못했으며 코드 검토로만 확인했습니다.

상단 헤더 오른쪽에 별도로 떠 있던 "저장소 열기 ▾" 버튼을 없애고, 그 진입점을 열려 있는 저장소 탭들 옆의 "+ 저장소 열기" 버튼으로 옮겼습니다(image-10.png에서 지적하신 것처럼 상단 우측 버튼이 아니라 탭 옆에 있어야 한다는 요청 반영). `renderRepoTabs()`가 항상 `#repo-tab-strip`을 보이는 상태로 유지하도록 바꿔서(이전에는 열린 저장소가 하나도 없으면 이 줄 자체가 숨겨졌습니다), 저장소를 하나도 열지 않은 상태에서도 탭 자리에 "+ 저장소 열기" 버튼만 남아 있고, 저장소를 열면 그 옆으로 탭이 하나씩 늘어납니다. 버튼이 여는 모달(`openRepoMenu`: 기존 저장소 열기 / `git init` / `git clone`)은 그대로 재사용해 새 코드 없이 위치만 옮겼습니다.

사이드바 맨 위 "현재 브랜치" 표시줄 위에 있던 저장소 이름 블록("개인 작업 공간" / "예제 데이터 · 로컬 시뮬레이션" 또는 실제 저장소명 / 실제 경로)을 제거했습니다. 같은 정보(저장소 이름, 예제·실제 구분)는 이미 상단 헤더의 저장소 탭(`#repo-tab-name`/`#repo-tab-tag`)에 표시되고 있어 사이드바에 중복으로 있을 필요가 없었고, 첨부 이미지(image-10.png)에서 브랜치 이름이 좁은 폭 때문에 "현재 브 랜치"처럼 라벨 자체가 줄바꿈되는 문제도 함께 보였습니다 — 이번 변경으로 그 블록이 차지하던 공간이 사라져 "현재 브랜치" 줄이 더 넓게 쓸 수 있게 됐습니다(줄바꿈 자체는 브랜치 이름이 아주 길면 여전히 발생할 수 있는 폭 문제라 별도 처리는 하지 않았습니다). `syncHeader()`에서 이 블록에 값을 채우던 두 줄(`repo-name-label`/`repo-name-sub`)도 함께 지웠는데, DOM에 없는 id에 `.textContent`를 대입하면 `null` 참조 에러가 나기 때문에 마크업만 지우고 이 코드를 남겨두면 안 됩니다 — 실제로 지웠는지 `npm test`의 스크립트 구문 검증과 `grep`으로 잔여 참조가 없는지 재확인했습니다. 두 변경 모두 마크업·렌더 타깃 정리라 `npm test`로 확인했고, 실제 클릭 상호작용은 Electron GUI가 없어 코드 검토로만 확인했습니다.

작업 변경 화면은 GitKraken처럼 메인 영역(선택한 파일의 diff 미리보기)과 오른쪽 사이드바(Unstaged Files / Staged Files 목록 + 커밋 작성 폼)로 나눈 2단 레이아웃(`work-split`)으로 바꿨습니다. 실제 저장소 모드에서 파일을 클릭하면 `diffFile` IPC(스테이징 여부에 따라 `staged`/기본 모드)를 호출해 메인 영역에 diff를 보여주고, 부분 스테이징이 되어 있어 unstaged/staged 양쪽에 동시에 나타나는 파일도 각 섹션에서 독립적으로 클릭·미리보기할 수 있습니다. 추적되지 않은(untracked) 신규 파일은 `git diff --no-index`의 종료 코드 처리가 기존 파이프라인과 달라 범위를 벗어난다고 판단해, 스테이징 전에는 안내 문구만 보여주고 실제 diff 조회는 시도하지 않습니다. 커밋을 완료하면 미리보기 상태를 초기화하고, 뷰 전환·저장소 탭 전환 시에도 기존 `fileViewer` 정리 패턴과 동일하게 초기화하도록 했습니다. 데모 모드에서는 파일별 diff 데이터가 없으므로 안내 문구만 표시합니다. 이 변경은 UI 레이아웃과 기존 `diffFile`/`diffLines` 재사용이 전부라 새로운 백엔드 검증은 필요 없었고, `npm test`(스크립트 구문 검사 포함)로 확인했습니다. 다만 Electron이 설치되어 있지 않아 실제 클릭으로 diff가 렌더링되는 모습은 GUI로 확인하지 못했고 코드 검토로만 확인했습니다. (참고: "작업 변경" 화면을 모달이 아닌, 닫기 버튼이 있는 오버레이 패널로 그래프 위에 띄우는 부분은 바로 다음 항목의 커밋 그래프 개편과 같은 턴에서 함께 처리되어 이미 적용되어 있었습니다 — 아래 문단 참고.)

커밋 그래프 필터링 방식을 요청하신 대로 바꿨습니다. 기존에는 `viewBranch`(그래프에 표시할 브랜치)가 항상 어떤 브랜치든 하나로 고정되어 있어서, 필터를 걸지 않은 "기본" 상태에서도 사실상 `viewBranch` 하나의 조상 이력만 보였습니다. 이제 `viewBranch`가 `null`일 수 있도록 바꿔 이 값을 "브랜치 필터가 꺼진 상태(전체 브랜치)"의 의미로 쓰고, `getRows()`는 `viewBranch`가 없으면 필터링 없이 `commits` 전체(모든 브랜치의 모든 커밋)를 반환하도록, `viewBranch`가 있으면 기존처럼 `reachable(refs[viewBranch])`로 그 브랜치의 이력만 반환하도록 나눴습니다. 그래프 화면 헤더에는 "조회할 브랜치" 대신 "브랜치 필터" 드롭다운을 새로 추가했는데, 첫 번째 옵션이 "전체 브랜치 (모든 커밋)"(값 없음 → `viewBranch=null`)이고 나머지는 기존처럼 각 브랜치입니다 — "이력 범위"(전체 조상 이력 / 다른 브랜치에 없는 이력) 선택지는 특정 브랜치를 필터링 중일 때만 의미가 있어 그때만 함께 보이도록 했습니다. 필터가 꺼져 있을 때는 브랜치 정보 바 대신 "전체 브랜치 · 로컬 브랜치 N개의 모든 커밋을 함께 표시 중 · 현재 체크아웃: X" 요약 바(`allBranchesInfoBar`)를 보여줘, 지금 보고 있는 게 특정 브랜치가 아니라 저장소 전체라는 점과 실제 체크아웃 브랜치가 무엇인지를 동시에 알 수 있게 했습니다. 사이드바에서 브랜치를 클릭/더블클릭하면(`selectBranchView`/`showBranch`) 그 브랜치로 필터가 걸리고, 드롭다운에서 "전체 브랜치"를 다시 선택하면(`setGraphFilter`) 필터가 풀립니다. `mapSnapshot`과 `resetDemo`도 저장소를 새로 열거나 초기화할 때 `viewBranch`를 실제 체크아웃 브랜치가 아니라 `null`(전체)로 리셋하도록 바꿔서, "기본 커밋 그래프는 checkout된 브랜치가 아닌 전체 커밋"이라는 요구사항이 저장소를 새로 열 때마다 지켜지도록 했습니다. `viewBranch`를 참조하던 나머지 코드(브랜치 비교 기본값, 내 메모, 커밋 상세의 "조회 브랜치" 표시)는 `viewBranch||branch`(필터가 없으면 실제 체크아웃 브랜치를 대신 사용) 형태로 null 안전하게 고쳤습니다.

헤더의 "Branch" 버튼과 메인 화면 안의 "브랜치 만들기" 버튼이 겹친다는 지적은 확인해보니 지난 턴(그래프를 오버레이 구조로 바꾸면서 그래프 헤더 자체를 없앤 시점)에 이미 정리되어 있었습니다 — 그래프 화면에는 더 이상 헤더도, "브랜치 만들기" 버튼도 없고, 브랜치 생성은 상단 헤더의 "Branch" 버튼과 ⌘K 빠른 실행 팔레트, 브랜치 우클릭 메뉴의 "여기서 브랜치 만들기"(특정 브랜치를 시작점으로 지정하는 용도라 중복이 아님)에서만 가능합니다. `grep`으로 `openNewBranch()` 호출부를 전부 확인해 실제로 메인 화면에 중복 버튼이 남아있지 않음을 재확인했습니다.

커밋 상세 패널이 화면을 열자마자 첫 번째 커밋을 자동으로 보여주던 것을 고쳐, 커밋을 직접 클릭했을 때만 표시되도록 했습니다. `activeId`의 기본값을 `'f1'`에서 `null`로 바꾸고, `renderHistory()`가 필터링된 목록이 바뀔 때 `activeId`를 목록의 첫 번째 커밋으로 대체하던 로직(`activeId=rows[0]?.id||null`)을 제거해 "그 목록에 없으면 그냥 비운다"(`activeId=null`)로 바꿨습니다. 브랜치 필터를 바꾸는 지점들(`selectBranchView`/`showBranch`/`setGraphFilter`/`resetDemo`)에서도 `activeId=null`을 명시적으로 함께 초기화해, 필터를 바꿨는데 이전 화면에서 클릭했던 커밋 상세가 그대로 남아있는 일이 없도록 했습니다. 커밋을 아무것도 선택하지 않은 상태의 안내 문구("커밋을 선택하면 변경 내용을 볼 수 있습니다")는 기존에 이미 있던 것을 그대로 활용했습니다. 이 변경들은 모두 순수 상태 초기화 로직이라 `npm test`로 스크립트 구문과 기존 모델 검증을 확인했고, 실제 클릭 시 상세 패널이 나타나고 사라지는 모습은 Electron GUI가 없어 코드 검토로만 확인했습니다.

상단 헤더의 Fetch/Push/Branch/Stash/Pop/Gitflow/Terminal 버튼을 GitKraken 실제 화면(image-11.png)처럼 테두리 없는 아이콘-위·글자-아래 버튼으로 바꿨습니다. 새 `.toolbar-btn` 클래스(테두리 투명, 호버 시에만 옅은 배경, `flex-direction:column`으로 아이콘 위·10px 라벨 아래 배치)를 추가했고, 기존 `.btn`/`.btn-secondary` 대신 이 클래스를 쓰도록 `syncHeader()`의 `#primary-actions` 마크업을 다시 짰습니다. 아이콘이 없던 Fetch/Push/Pop/Terminal용 획(stroke) 기반 SVG 경로도 새로 추가했습니다(Stash/Branch는 기존 아이콘 재사용). 참고 이미지처럼 버튼 그룹 사이에 얇은 세로 구분선(`.toolbar-divider`)도 넣었습니다. "빠른 실행 ⌘K" 버튼은 GitKraken에서도 아이콘 툴바와 분리된 검색창 스타일이라 이번 변경 대상에서 제외하고 기존 테두리 있는 버튼 그대로 뒀습니다.

기존에 별도 "Fetch"/"Pull" 두 버튼으로 나뉘어 있던 것을 GitKraken처럼 "Fetch ▾" 하나로 합치고, 클릭하면 Fetch와 세 가지 Pull 전략(Fast-forward if possible / Fast-forward only / Rebase)을 보여주는 드롭다운 메뉴가 뜨도록 했습니다(`openFetchMenu`, 기존 커밋·브랜치 우클릭 메뉴가 쓰던 `#context-menu` 엘리먼트와 위치 계산 로직을 그대로 재사용해 버튼 아래에 앵커링). 이 세 전략은 기존에 백엔드에서 지원하지 않던 기능이라 `git-backend.cjs`의 `pull` 함수에 전략별 플래그 매핑(`ff`→`--ff`, `ff-only`→`--ff-only`, `rebase`→`--rebase`, 기본값은 플래그 없음 = 기존 동작과 동일)을 추가하고, `electron-main.cjs`의 `git:pull` 핸들러와 프런트엔드 `pullRepo(strategy)`까지 그 값을 그대로 전달하도록 연결했습니다. 실제로 원격과 로컬이 갈라진(diverged) 임시 저장소 3벌을 만들어 직접 검증했습니다: (1) `ff-only`는 병합 커밋이 필요한 상황에서 실제로 거부되는 것, (2) 같은 파일의 같은 줄을 건드려 충돌이 나는 rebase는 `operationState()`가 기존 rebase 충돌 감지 코드 그대로 `'rebase'`를 반환하고 `conflictedFiles`가 채워지며 `abortOperation('rebase')`로 정상 복구되는 것(즉 새 코드를 추가하지 않고 기존 충돌 배너·중단 흐름이 그대로 재사용됨), (3) 서로 다른 파일을 건드린 경우 rebase가 충돌 없이 깔끔하게 커밋을 앞으로 재배치하는 것, (4) 기본(`ff`) 전략은 diverged 상황에서 실제로 병합 커밋을 만드는 것까지 라이브로 확인했습니다. `npm test`도 통과했고, 툴바 버튼의 실제 렌더링·클릭·드롭다운 위치는 Electron GUI가 없어 코드 검토로만 확인했습니다.

사이드바 LOCAL 섹션이 REMOTE/TAGS/STASHES와 다른 마크업을 쓰고 있던 불일치(image-12.png에서 지적하신 부분)를 고쳤습니다. REMOTE/TAGS/STASHES는 전부 `<details><summary>`(펼침/접힘 가능, `›`/`⌄` 화살표가 `::before`로 붙는 공통 스타일)로 되어 있었는데, LOCAL만 예전 코드가 남아 `<div class="branch-group"><p class="side-label">...`라는 별도 마크업을 쓰고 있어서 화살표도 없고 접을 수도 없이 혼자 다른 모양이었습니다. LOCAL도 나머지와 완전히 같은 `<details><summary>` 구조로 바꾸되(아이콘·"LOCAL"·개수 배지·솔로/숨김 컨트롤 순서는 그대로 유지), 항상 펼쳐진 상태로 시작하도록 `open` 속성만 추가해 브랜치 목록이 기본적으로 안 보이는 회귀가 생기지 않게 했습니다(REMOTE/TAGS/STASHES는 원래도 `open` 없이 접힌 채 시작하므로 그대로 뒀습니다). 이제 4개 섹션 모두 같은 `.sidebar details summary` 규칙 하나로 화살표·간격·호버가 통일됩니다. 이 과정에서 더 이상 쓰이지 않게 된 `.side-label`, `.branch-group` CSS 규칙과 모바일 미디어 쿼리의 `.sidebar .branch-group` 참조도 함께 지웠습니다(`grep`으로 잔여 참조가 없는지 재확인). 순수 마크업·CSS 정리라 `npm test`로 스크립트 구문을 확인했고, 실제 접힘/펼침 클릭 상호작용은 Electron GUI가 없어 코드 검토로만 확인했습니다.
